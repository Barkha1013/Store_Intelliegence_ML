PART A — DETECTION PIPELINE (30 pts)
════════════════════════════════════════════════════
Build pipeline/detect.py using:
  - Detection model: YOLOv8n or YOLOv8s (ultralytics) — justify choice in CHOICES.md
  - Tracking: ByteTrack (built into ultralytics) — one tracker instance per camera
  - Re-ID: OSNet (torchreid) or bounding-box trajectory cosine distance for cross-camera dedup
  - Staff detection: classify by bounding-box aspect ratio + color histogram of torso region
    vs a reference uniform color loaded from store_layout.json["staff_uniform_hsv"]

Handle ALL these edge cases explicitly in code:
  1. GROUP ENTRY: if N bbox centroids cross the entry line within 2 seconds, emit N ENTRY events
  2. STAFF: set is_staff=True, EXCLUDE from all customer metrics but still emit events
  3. RE-ENTRY: if same Re-ID embedding matches a visitor_id that previously had EXIT, emit REENTRY
     not a new ENTRY — reuse the same visitor_id
  4. PARTIAL OCCLUSION: if detection confidence < 0.45, still emit the event; set confidence field
     accurately — never round up
  5. BILLING QUEUE: maintain a queue_depth counter per store; emit BILLING_QUEUE_JOIN when
     a visitor enters the billing zone while queue_depth > 0
  6. CAMERA OVERLAP: cross-camera dedup using Re-ID — if the same embedding appears on both
     entry cam and floor cam within 30s, treat as same visitor_id, don't double-count
  7. EMPTY STORE: if no detections for 5+ minutes, emit a STORE_IDLE synthetic event (extend 
     the schema — document this extension in DESIGN.md)

Event schema (emit exactly this, validated by Pydantic):
{
  "event_id": "uuid-v4",
  "store_id": "STORE_BLR_002",
  "camera_id": "CAM_ENTRY_01",
  "visitor_id": "VIS_c8a2f1",
  "event_type": "ZONE_DWELL",          // ENTRY|EXIT|ZONE_ENTER|ZONE_EXIT|ZONE_DWELL|
                                        // BILLING_QUEUE_JOIN|BILLING_QUEUE_ABANDON|REENTRY
  "timestamp": "2026-03-03T14:22:10Z", // ISO-8601 UTC — clip start time + frame/fps offset
  "zone_id": "SKINCARE",               // null for ENTRY/EXIT
  "dwell_ms": 8400,
  "is_staff": false,
  "confidence": 0.91,
  "metadata": {
    "queue_depth": null,
    "sku_zone": "MOISTURISER",
    "session_seq": 5
  }
}

BILLING_QUEUE_ABANDON logic:
  - Visitor entered billing zone (BILLING_QUEUE_JOIN emitted)
  - Visitor exits billing zone via EXIT or ZONE_EXIT
  - No POS transaction for this store within 5 minutes after exit
  - → emit BILLING_QUEUE_ABANDON retroactively (mark in DB, emit on next API poll)

PART B — INTELLIGENCE API (35 pts)
════════════════════════════════════════════════════
Build with FastAPI + SQLite (use aiosqlite for async). Schema:

Tables:
  events(event_id PK, store_id, camera_id, visitor_id, event_type, timestamp,
         zone_id, dwell_ms, is_staff, confidence, metadata JSON, ingested_at)
  sessions(session_id PK, store_id, visitor_id, entry_time, exit_time,
           converted BOOL, basket_value_inr REAL)

Endpoints — implement all of these:

POST /events/ingest
  - Accept batch up to 500 events
  - Validate each event against Pydantic schema
  - Deduplicate by event_id (idempotent — calling twice with same payload = same result)
  - Partial success: if 3 of 500 are malformed, ingest 497 and return errors for 3
  - Response: {"ingested": 497, "duplicates": 0, "errors": [{"event_id":..., "reason":...}]}
  - Log: trace_id, store_id, latency_ms, event_count, status_code

GET /stores/{store_id}/metrics
  - Returns for today (UTC):
    unique_visitors (int, customer-only — exclude is_staff=true)
    conversion_rate (float 0-1)
    avg_dwell_per_zone (dict: zone_id → avg_ms)
    current_queue_depth (int)
    abandonment_rate (float 0-1)
  - Zero-purchase stores: conversion_rate = 0.0, not null, not error
  - Real-time: query DB live, no caching

GET /stores/{store_id}/funnel
  - Session is the unit (not raw events)
  - Stages: entry_count → zone_visit_count → billing_queue_count → purchase_count
  - drop_off_pct between each stage
  - Re-entries: a visitor_id that REENTRY-ed counts as 1 unique visitor in funnel

GET /stores/{store_id}/heatmap
  - Per zone: visit_frequency (int), avg_dwell_ms (int), normalised_score (0-100)
  - data_confidence: "LOW" if fewer than 20 sessions in the window, else "HIGH"

GET /stores/{store_id}/anomalies
  - Detect:
    BILLING_QUEUE_SPIKE: queue_depth > 5 for 3+ consecutive minutes → CRITICAL
    CONVERSION_DROP: today's rate < 7-day average × 0.8 → WARN
    DEAD_ZONE: a zone with 0 visits in last 30 minutes (during store open hours) → INFO
    STALE_CAMERA: no events from a camera_id for 10+ minutes → WARN
  - Each anomaly: {type, severity, description, suggested_action, detected_at}

GET /health
  - {status: "ok"|"degraded", last_event_per_store: {store_id: timestamp},
     stale_feeds: [store_id], db_status: "connected"|"unavailable", uptime_seconds}
  - If DB unavailable → still return 200 with db_status:"unavailable", not 500
